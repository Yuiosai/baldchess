# BaldChess 5.13 — публикация в интернете (тестовый запуск)

## 1. Загрузите проект в GitHub

1. Создайте аккаунт на https://github.com, если его ещё нет.
2. Создайте репозиторий с именем `baldchess` (можно Private). При создании **не добавляйте** файлы README или .gitignore автоматически: они уже включены в проект.
3. Распакуйте архив, откройте папку `BaldChess`.
4. В пустом репозитории GitHub нажмите `uploading an existing file` / `Add file` → `Upload files`.
5. Загрузите **содержимое папки** `BaldChess` (папки `js`, `assets`, файл `server.py` и др.). Файл `render.yaml` должен оказаться **в корне репозитория**, рядом с `server.py` и `index.html`, а не внутри дополнительной папки.
6. Нажмите `Commit changes`.

**Важно:** не выкладывайте настоящую базу `rooms.sqlite3`, токены игроков, ключи API, приватные данные. Архив содержит только пустой `data/rooms.json`, без личных партий. Для публикации достаточно исходников.

## 2. Создайте бесплатный Web Service в Render

1. Зарегистрируйтесь на https://dashboard.render.com.
2. Нажмите `New` → `Blueprint` и подключите ваш GitHub-репозиторий.
3. Укажите путь к конфигурации `render.yaml` (корень; Render найдёт файл автоматически).
4. Проверьте параметры: тип Web Service, `Python`, тариф **Free**. Не выбирайте платный план без необходимости.
5. Нажмите `Deploy Blueprint` и дождитесь запуска. Render сам выполнит сборку и команду `python server.py --no-browser`.
6. В разделе сервиса появится ссылка `https://<ваше-название>.onrender.com`. Откройте её и создайте тестовую комнату.

Альтернатива Blueprint: `New` → `Web Service`, репозиторий, runtime `Python`, build command `python -m compileall -q server.py engine.py`, start command `python server.py --no-browser`, план `Free`.

## 3. Как проверить игру

- Откройте сайт на двух устройствах или в разных профилях браузера. Создайте комнату с одного и войдите в неё по коду с другого.
- Проверьте ход, переключение очереди, часы, смену скина, обновление страницы, возврат по тому же URL.
- Убедитесь, что попытка изменить правила комнаты со второго игрока отклоняется.

## Важно: ограничения тестового бесплатного запуска

На Free Render сервис засыпает через 15 минут без входящих запросов; при следующем открытии может потребоваться около минуты на пробуждение. Бесплатный сервер **теряет локальные SQLite-файлы**, включая комнаты и токены игроков, при засыпании, рестарте или новом деплое. Это нормальное ограничение тестового варианта, а не надёжное хранение партий.

Для постоянного сайта можно перейти на платный сервер Render с persistent disk (тогда установить переменную `BALDCHESS_DB` в путь на смонтированном диске, например `/var/data/rooms.sqlite3`) или переделать приложение под внешнюю базу. Текущая серверная логика предполагает один запущенный процесс; не запускайте её одновременно на двух независимых экземплярах.

Домен покупать не нужно: бесплатный `*.onrender.com` адрес уже работает с HTTPS. Собственный домен можно привязать позже.

## Если ошибка при публикации

- `render.yaml not found` — файл лежит не в корне репозитория.
- `Port scan timeout` — проверьте, что start command `python server.py --no-browser`, `PORT` не жёстко задан на 8000.
- `Application failed to respond` — смотрите вкладку `Logs` в Render. Путь `server.py` должен быть в корне.
- Ошибка приложения после длительного простоя — Free-сервер мог заснуть или перезапуститься; тестовые комнаты могут быть потеряны.
